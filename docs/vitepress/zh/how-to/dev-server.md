# 用开发服务器调试主题

主题开发阶段可配置 foobar2000 直接从 Vite 等本地开发服务器加载页面（利用 HMR 热模块重载特性），免去每次修改后重新构建与复制文件的步骤。完整流程见[构建第一个主题](/zh/tutorials/first-theme)。

## 让 foobar2000 指向开发服务器

1. 启动本地开发服务器，记下它的地址，例如 `http://localhost:5173`。
2. 打开 `File → Preferences → Display → WebView2 UI` 下的 `开发者` 页。
3. 勾选 `使用开发服务器（HMR 热重载）`，在 `URL` 框里填入完整地址。地址必须以 `http://` 或 `https://` 开头并包含主机名。
4. 按 `应用`。

主窗口和跟随全局模板的面板立即重新加载，无需重启宿主。指定了专属模板或 URL 的面板，下一次加载页面时同样从开发服务器加载。弹出窗口打开同一服务器上的 `<服务器>/<页面>.html`。

宿主完全信任从该指定地址加载的前端页面，因此 `fb2k.invoke()` 和 SDK 在开发服务器页面中均可正常调用。受信任域依据协议（Scheme）、主机名（Host）与端口号（Port）进行精确匹配：运行在其他端口的页面，或配置为 `localhost` 但实际使用 `127.0.0.1` 访问的页面，均无法调用宿主 API。详见[哪些页面能调用 API](/zh/reference/security#哪些页面能调用-api)。

前端页面或构建脚本亦可通过 `fb.ui.setDevServerConfig({ useDevServer, devServerUrl })`（底层宿主端点 `window.setDevServerConfig`）以编程方式调整上述两项配置。配置将被持久化保存，并在下一次重新加载页面时生效。

## 页面未更新仍显示旧模板的排查 {#出现的还是原来的主题}

若宿主无法连通指定的开发服务器，将自动回退加载已安装的本地模板。排查时请确认开发服务器进程正在运行，且监听端口与填写的 URL 完全一致（推荐在 Vite 配置中开启 `strictPort: true` 防止端口静默漂移）；确认无误后再次单击「应用」或重启 foobar2000。

## 打开开发者工具

- 在同一偏好设置页勾选 `启用开发者工具 (F12)`。该设置在 WebView 实例创建时读取，修改后需重启 foobar2000。启用后，无论是否使用开发服务器，在任意 WebView 中按 F12 均可唤出 DevTools 调试面板。
- 主窗口从开发服务器加载页面时，DevTools 默认自动弹出。
- 面板可在自身的属性配置对话框中单独开启开发者工具，即时生效无需重启，见[把页面放进面板](./panels.md#给面板指定自己的模板或-url)。

宿主禁用了 WebView2 默认右键菜单，因此不提供「检查元素」菜单项，页面自定义右键事件逻辑不受干扰。

## 切回已安装的本地模板 {#回到已安装的模板}

取消勾选 `使用开发服务器（HMR 热重载）`，按 `应用`。如需将开发成果正式部署为永久主题，先执行构建，再将产物复制至模板目录，见[安装主题](./install-theme.md)。

## 自动化与 CDP 远程调试 {#供自动化用的远程调试}

偏好设置页中的 `CDP 远程调试` 允许 WebView 在本地指定端口（默认 9222）上开放 Chrome DevTools Protocol 接口，供 MCP 服务或外部脚本进行自动化控制。修改后重启生效，详见 [MCP 配置指南](/zh/mcp/setup)。
