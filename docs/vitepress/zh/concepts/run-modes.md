# 运行模式

同一个前端页面可在三种宿主模式下运行，宿主模式决定了页面对窗口的控制权限范围。

| 模式 | 页面承载位置 | 页面控制范围 |
| --- | --- | --- |
| 独立窗口 | 作为 Default User Interface 的顶层用户界面，页面承载整个 foobar2000 窗口 | 顶层窗口本身：尺寸、标题栏、系统材质背景、托盘图标、任务栏按钮 |
| DUI 面板 | Default UI 布局中的 `WebView2 Panel` 面板元素 | 仅限面板自身的可视矩形区域 |
| CUI 面板 | Columns UI 布局中的 `WebView2 Panel` 面板元素 | 仅限面板自身的可视矩形区域 |

[后台模式](/zh/how-to/background-mode)提供第四种运行方式：在保留 Default UI 或 Columns UI 为主界面的同时，独立弹出或隐式运行一个 WebView2 UI 辅助窗口。

## 不变的部分

所有模式下运行的均为标准前端页面，并共享相同的 Bridge 通道。播放控制、播放列表、媒体库、封面提取、元数据、配置存储等 foobar2000 核心命名空间通用，`fb.*` 方法与 `fb-*` Web Components 无需区分运行环境。主题因而可以使用单一代码库同时适配独立窗口与面板。

## 面板模式的差异与限制 {#面板里有什么不同}

面板作为第三方界面所属窗口中的子区域，无法直接操作宿主顶层窗口：

- 涉及顶层窗口管理的 `window.*` 方法（尺寸与位置调整、窗口状态、拖动区域、标题栏覆盖、Mica/Acrylic 材质、窗口圆角、窗口置顶等），由面板调用时均以 `PANEL_MODE_UNSUPPORTED` 失败。
- 当 WebView2 UI 未作为顶层用户界面运行时，`tray.*` 与 `taskbar.*` 端点因缺乏宿主顶层窗口归属，同样以 `PANEL_MODE_UNSUPPORTED` 失败。
- 每个面板拥有独立的配置项：可配置专属模板或 URL，并单独设定透明度、焦点捕获、拖放支持及 DevTools 开关。

页面可通过 `window.getMode` 运行时探测自身所处模式；具体适配方案见[把页面放进面板](/zh/how-to/panels#让页面适应面板)。

## 架构选型考量 {#为什么有三种模式}

接管整个界面能让主题获得完整的窗口定制能力；但在实际应用中，许多用户更倾向于保留 Default UI 或 Columns UI 成熟的播放列表与媒体库视图，仅将网页用作封面展示、歌词联动、音频频谱或状态监控条。面板模式正是为这一场景设计，开发者无需重写 foobar2000 界面的全部原生功能。
